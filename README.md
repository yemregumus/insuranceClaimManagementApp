# Insurance Claim Management Application

## Overview

The Insurance Claim Management application is a web-based solution
designed for insurance-company staff to manage customers and claims. Each company
is isolated as an organization so its staff cannot access another company's data.

## Purpose

The purpose of this application is to provide a user-friendly interface for managing insurance claims,
making it easier for users and administrators to track and update claim statuses.
It aims to enhance the overall efficiency of insurance claim processing.

## Features

- **User Management**:
  - Create, read, update, and delete user profiles.
  - Store user details including name, email, and username.

- **Staff Identity and Access**:
  - ASP.NET Core Identity password hashing and lockout protection.
  - Administrator, claims-adjuster, and read-only roles.
  - Organization-scoped staff administration and account deactivation.
  - Self-service password changes.
  - Two-hour account setup and recovery links generated by organization administrators.
  - Optional authenticator-app two-factor authentication and single-use recovery codes.

- **Multi-company isolation**:
  - Staff, customers, and claims belong to an organization.
  - Application query filters and database foreign keys enforce tenant boundaries.

- **Claims Management**:
  - Create, read, update, and archive insurance claims.
  - Track claim types, descriptions, amounts, statuses, and associated user information.
  - Preserve status history and detect conflicting staff updates.

- **Dashboard**:
  - View lists of users and claims in a comprehensive dashboard.

## Tech Stack

- **Frontend**:
  - ASP.NET Core Razor Pages for building dynamic web pages.
  - HTML, CSS, and Bootstrap for responsive design and layout.

- **Backend**:
  - ASP.NET Core for building the server-side logic and handling requests.
  - Entity Framework Core for data access and manipulation.

- **Database**:
  - MySQL for storing customer, claim, and staff identity data.

- **Development Tools**:
  - Visual Studio for development.
  - Git for version control.

## Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/yourusername/InsuranceClaimManagement.git
   ```
2. Navigate to the project directory:
   ```bash
   cd InsuranceClaimManagement
   ```
3. Restore the dependencies and repository-local tools:
   ```bash
   dotnet restore
   dotnet tool restore
   ```
4. Store the local database connection with .NET User Secrets:
   ```bash
   dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=localhost;Port=3306;Database=InsuranceClaimDB;User=YOUR_USER;Password=YOUR_PASSWORD"
   ```
5. Back up an existing database, then apply the migrations:
   ```bash
   dotnet ef database update
   ```
6. Provision an organization and its initial administrator without placing its password in source control:
   ```powershell
   $env:InitialAdmin__Email = Read-Host "Admin email"
   $securePassword = Read-Host "Admin password" -AsSecureString
   $env:InitialAdmin__Password = [System.Net.NetworkCredential]::new("", $securePassword).Password
   $env:InitialOrganization__Name = "Your Insurance Company"
   $env:InitialOrganization__Slug = "your-company"
   dotnet run -- --provision-organization
   Remove-Item Env:InitialAdmin__Email
   Remove-Item Env:InitialAdmin__Password
   Remove-Item Env:InitialOrganization__Name
   Remove-Item Env:InitialOrganization__Slug
   Remove-Variable securePassword
   ```
   The password must be at least 12 characters and contain uppercase and lowercase
   letters, a number, and a symbol. Provisioning prints each unmet requirement and
   does not create the account when validation fails. Organization slugs use lowercase
   letters, numbers, and single hyphens. A staff email cannot belong to multiple organizations.
7. Start the application:
   ```bash
   dotnet run
   ```

## Usage

- Access the application through your web browser at `http://localhost:5000`.
- Sign in with a provisioned staff account.
- Administrators can manage customers and claims.
- Administrators can create, assign roles to, and deactivate staff in their own organization.
- Until an email provider is configured, administrators must privately share the one-time
  password setup link shown after account creation. The link expires after two hours.
- Claims adjusters can manage claims.
- Read-only staff can view claims and dashboard totals.
- Signed-in staff can change their own password from the Security page.
- Staff can enable authenticator-app two-factor authentication from the Security page.
- Administrators can reset two-factor authentication after verifying a locked-out staff member's identity.

## Testing

Run the complete automated test suite from the repository root:

```powershell
dotnet test InsuranceClaimManagement.Tests\InsuranceClaimManagement.Tests.csproj
```

Run the tests and enforce the 80% application line-coverage requirement:

```powershell
& .\InsuranceClaimManagement.Tests\Test-WithCoverage.ps1
```

The coverage gate measures the `InsuranceClaimManagement` application assembly and
excludes generated Razor output, EF migration code, build output, and the executable
host entry point. Tests are grouped by the behavior they verify:

- `Account`: login, password, authenticator, QR-code, and recovery workflows.
- `Claims`: claim validation, status history, updates, and archival.
- `Customers`: customer creation, uniqueness, editing, and deletion safeguards.
- `Data`: organization and administrator provisioning.
- `Pages`: dashboard, list, audit, and tenant-scoped read behavior.
- `Staff`: staff creation, roles, deactivation safeguards, setup links, and 2FA reset.
- Root-level validation, authorization, and tenant-isolation tests cover shared rules.

Files under `bin` and `obj` are generated build artifacts and must not be edited or committed.
